# Change log: 2026-10-03 / 001

- **Date:** 2026-10-03
- **Summary:** Established the Laravel 12 multi-database tenancy foundation with
  organization provisioning, isolated tenant users and roles, development
  resolution modes, environment templates, and foundation documentation.
- **Files added/changed/removed:** Added `app/Models/Organization.php`,
  `app/Models/Domain.php`, tenancy configuration and middleware, tenant
  migrations and seeders, environment templates, and documentation. Changed
  application bootstrapping, the tenancy provider, tenant routes, central
  migrations, the central seeder, Composer dependencies, `.env.example`, and
  `README.md`. Removed the central users migration because users belong in each
  tenant database.
- **Migrations:** Run central migrations in `database/migrations`, then tenant
  migrations in `database/migrations/tenant` through provisioning.
- **New env vars:** `TENANCY_RESOLUTION`, `TRUSTED_PROXIES`,
  `DEMO_ADMIN_EMAIL`, and `DEMO_ADMIN_PASSWORD`.
- **Commands to run:** `composer install`, copy the appropriate environment
  example to `.env`, `php artisan key:generate`, `php artisan migrate`, and
  `php artisan db:seed`.
- **Breaking changes:** Authentication users are no longer stored in the central
  database. Existing central user data must be migrated into the corresponding
  tenant database before adoption.
- **Manual steps:** Create the central MySQL database and use a MySQL account
  allowed to create tenant databases and users. Set a non-default demo password
  before seeding outside disposable development environments. Configure
  `APP_URL` and path or wildcard-subdomain routing for the chosen resolution
  mode.
