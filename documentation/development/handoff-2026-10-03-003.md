## What changed since handoff 002
- **Commit `9e845cb` / changelog 017**: fixed the Keycloak entrypoint
  (`.devcontainer/keycloak-entrypoint.sh`). It previously used `sed` to render
  the realm-import JSON template; the Keycloak image is minimal and most
  likely has no `sed`, so under `set -e` the container would exit before
  Keycloak started, leaving port 8081 returning 502 and the `keycloak`
  hostname unresolvable. The template is now rendered with a POSIX-shell-only
  `replace_all()` helper; output is identical.
  - **Not yet verified against a real container** — this session still has no
    Docker access (see below), so the fix is unexercised. Verifying it is the
    first thing to do once Docker access is available (handoff 002's step 2:
    remove the `keycloak-data` volume, recreate the `keycloak` service, check
    logs/port 8081, then run `saml:import-metadata` and test SSO login).

## Docker access from the app container
The devcontainer's `app` service (where this session runs) has no Docker
socket or CLI — it can't see or control sibling services (`mysql`, `redis`,
`keycloak`, etc.) defined in `.devcontainer/docker-compose.yml`. Two ways to
get access:

1. **SSH into the Codespace VM (no rebuild needed)**, from a local machine
   with the GitHub CLI signed in:
   ```sh
   gh codespace list
   gh codespace ssh -c <codespace-name>
   ```
   This reaches the VM's host shell, which has a real Docker engine. From
   there, `cd` to the repo checkout and run the `docker compose ...` commands
   from handoff 002 step 2 directly.
2. **Add Docker access to the devcontainer itself (needs a rebuild)**: add the
   `ghcr.io/devcontainers/features/docker-outside-of-docker:1` feature to
   `.devcontainer/devcontainer.json`, then rebuild the container. After that,
   `docker` / `docker compose` work directly from the app container's
   terminal, no separate SSH required. Not yet applied — still to decide/do.
