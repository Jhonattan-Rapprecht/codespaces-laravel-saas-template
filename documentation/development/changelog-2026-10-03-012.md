# Change log: 2026-10-03 / 012

- **Date:** 2026-10-03
- **Summary:** Unblocked the local Keycloak identity provider with fixed
  development credentials and a demo realm user, and added a command to configure
  an organization's SAML connection from IdP metadata.
- **Files added/changed/removed:** Moved the realm to
  `.devcontainer/keycloak/realm-template/` with `__APP_URL__` and
  `__DEV_USER_PASSWORD__` placeholders and a demo user (`admin@demo.test`); the
  entrypoint now renders it and no longer generates a random admin password;
  Docker Compose passes `KEYCLOAK_ADMIN_PASSWORD`, `KEYCLOAK_DEV_USER_PASSWORD`,
  `APP_PUBLIC_URL`, and Codespaces variables; added
  `App\Console\Commands\ImportSamlMetadata` and its test; rewrote
  `keycloak-development.md`.
- **Migrations:** None.
- **New env vars:** `KEYCLOAK_ADMIN_PASSWORD`, `KEYCLOAK_DEV_USER_PASSWORD`,
  `APP_PUBLIC_URL` (all optional, Keycloak container only).
- **Commands to run:** `php artisan saml:import-metadata <slug> <metadata-url>
  [--forwarded-host=...] [--enable]`.
- **Breaking changes:** The previous random bootstrap admin password mechanism is
  removed; `keycloak-data` volumes created earlier keep their old admin password.
- **Manual steps:** Rebuild the devcontainer and recreate the `keycloak-data`
  volume so the realm is re-imported (the realm is skipped when it exists), then
  run `saml:import-metadata` to pick up the new signing certificate. Not yet
  verified end to end: this container has no Docker access.
