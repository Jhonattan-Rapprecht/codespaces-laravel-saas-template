## What exists
- Superadmin back office `/admin` (own guard): organizations, suspend/activate,
  per-organization modules and SAML settings.
- Tenant area `/t/{slug}`: login (SSO link when SAML is enabled, otherwise a
  rate-limited email/password form), dashboard, Team and Settings modules.
- Tenant roles `tenant-admin` and `member`. Admins create users, change roles
  and set passwords on the Team page; the last admin cannot be demoted; SAML
  users get `member` on first sign-in.
- `php artisan saml:import-metadata <slug> <metadata-url> [--forwarded-host=]
  [--enable]` configures SAML from IdP metadata.
- README with feature list and screenshots in `documentation/screenshots/`.

## Local state that is NOT in git (will be lost or must be redone)
- `.env` (`APP_URL` was set to the Codespaces port-8000 URL).
- The central and tenant databases live in the MySQL volume. They survive a
  plain restart; a volume reset needs `php artisan migrate`,
  `php artisan db:seed`, `php artisan superadmin:create` and
  `php artisan tenants:migrate`.
- The superadmin account (`admin@saas.test`) was created by hand with a random
  password that is not recorded anywhere: create a new one with
  `php artisan superadmin:create`.
- The demo organization's SAML connection was set against the old Keycloak realm
  keys and is **disabled**; the demo tenant uses password login
  (`admin@demo.test` / `password`).
- `public/build` is ignored: run `npm run build`.
- The MySQL grant for the `laravel` user is persisted in
  `.devcontainer/mysql-init` but only applies to a fresh MySQL volume.

## Next steps, in order
1. Push the commits (`git push origin main`).
2. After rebuilding the devcontainer, verify Keycloak SSO end to end. Keycloak
   only imports its realm when the realm does not exist, so remove the
   `keycloak-data` volume once (from the host terminal, not the app container):
   ```sh
   docker compose -f .devcontainer/docker-compose.yml down keycloak
   docker volume rm "$(docker volume ls -q | grep keycloak-data)"
   docker compose -f .devcontainer/docker-compose.yml up -d keycloak
   ```
   Then run:
   ```sh
   php artisan saml:import-metadata demo \
     http://keycloak:8080/realms/saas-dev/protocol/saml/descriptor \
     --forwarded-host="${CODESPACE_NAME}-8081.${GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN}" \
     --enable
   ```
   Make port 8081 public/reachable, open `<APP_URL>/t/demo/login`, choose SSO
   and sign in as `admin@demo.test` / `Demo-Sso-Pass-1`. Keycloak admin console:
   `admin` / `keycloak-dev-admin`. All development-only credentials. Things

   URL matches the app URL, and entity ID/SSO URL use the forwarded host. Fix
   whatever breaks and record it in a new changelog.
