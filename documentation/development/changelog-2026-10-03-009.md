# Change log: 2026-10-03 / 009

- **Date:** 2026-10-03
- **Summary:** Prepared the demo organization for local Keycloak SAML sign-in in
  Codespaces. The end-to-end login is parked (see Manual steps). Also fixed
  central database seeding and added the missing `sessions` table migration.

  `name` attributes.
- **Breaking changes:** None.
- **Manual steps (parked, Keycloak login unresolved):**
  1. The `laravel` MySQL user needs privileges to create tenant databases
     (`GRANT ALL PRIVILEGES ON *.* TO 'laravel'@'%'`); this was applied by hand
     and is not persisted in the devcontainer configuration.
  2. Sign in to the Keycloak admin console (port `8081`) as `admin`. The
     generated password is read with the command in
     `documentation/user/keycloak-development.md`; it was not retrievable from
     inside the app container (no Docker access).
  3. In realm `saas-dev`, set client `urn:laravel-saas:demo` ACS (POST) URL and
     valid redirect URI to `<APP_URL>/t/demo/saml/acs`. The realm import only
     allows `http://localhost:8000/*`, and Keycloak skips re-importing an
     existing realm.
  4. Create a Keycloak user with an email and first name (mapped to `name`).
  5. Test `<APP_URL>/t/demo/saml/login`.
  6. Update `keycloak-development.md`: Keycloak's entity ID and SSO URLs follow
     the hostname it is reached on, not always `http://localhost:8081`.
