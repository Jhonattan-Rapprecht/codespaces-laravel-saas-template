# Change log: 2026-10-03 / 010

- **Date:** 2026-10-03
- **Summary:** Tenant login now shows an email/password form when the
  organization's SAML sign-in is disabled or unconfigured; SSO remains the only
  option while it is enabled.
- **Files added/changed/removed:** Updated `Tenant\LoginController` (new
  `store` action with rate limiting), `routes/tenant.php` (`POST /login`), the
  tenant login view, `TenantAccessTest`, `tenant-access.md`, and a tenant cache-tables migration.
- **Migrations:** Tenant migration `2026_10_03_000003_create_tenant_cache_tables` (cache tables in each organization database, needed because the cache driver is `database`; run `php artisan tenants:migrate`).
- **New env vars:** None.
- **Commands to run:** `php artisan tenants:migrate`, `php artisan test --filter=TenantAccessTest`.
- **Breaking changes:** Organizations without enabled SAML previously showed
  only a notice; they now allow password sign-in.
- **Manual steps:** None. Users created via SAML have random passwords and need
  one set before they can use the form.
